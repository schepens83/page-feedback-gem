The product loop

Review state and export history stay separate. This is what allows an approved comment edited after export to become ready again without rewriting history.

Host remains in control

The host supplies identity and authorization callbacks and retains its database, session, middleware, layout, and deployment boundary.

Untrusted context stays bounded

Captured HTML is escaped, request fields are capped, CSRF stays on, and replay accepts only same-origin local paths.

Review and export stay independent

Pending, approved, and rejected are review decisions. Export items record exact historical revisions without adding another comment status.

Meaningful changes become ready again

Canonical SHA-256 fingerprints include only exported content and the host source location. Timestamp and actor-only changes remain stable.

Open by default, explicit in code

Anonymous actor resolution and open capture/review policies make the engine usable without authentication. Host callbacks receive the active engine controller and denied requests return 403.

Rails-native browser boundary

The engine appends its Importmap and cache sweeper paths, exposes namespaced module pins, and reuses the host's Action View helpers.
